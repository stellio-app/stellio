# インストール

| プラットフォーム | ファイル／方法 | モード |
|---|---|---|
| 🪟 Windows | `Stellio-Setup-<version>.exe` | デスクトップアプリ |
| 🪟 Windows ポータブル | `Stellio-v<version>-portable-win64.zip` | デスクトップアプリ（インストール不要） |
| 🍎 macOS | `.dmg`（Apple Silicon `arm64` または Intel `x86_64`） | デスクトップアプリ |
| 🐧 Linux | `Stellio-v<version>-x86_64.AppImage` | デスクトップアプリ |
| 🍓 Raspberry Pi / Linux | `install-pi.sh` | サーバー（ブラウザ） |
| 🖥️ Proxmox VE | `stellio-lxc.sh` | コマンド 1 つで LXC コンテナ |
| 📲 Android | コンパニオン APK | [リモート／モバイルアクセス](ja-Remote-Access) を参照 |

すべてのファイルは [Releases](https://github.com/stellio-app/stellio/releases) ページにあり、それぞれ `.sha256` チェックサムが付いています。

## Windows

1. Releases からインストーラーをダウンロードします。
2. `Stellio-Setup-<version>.exe` を実行します。
3. 完了です。

**ポータブル版**：好きな場所（ディスク、USB メモリ）に展開して `Stellio.exe` を実行します。データは実行ファイルの隣の `data` フォルダーに保存されます（`portable.flag` ファイルは残してください）。

> ⚠️ インストーラーは**コード署名されていません**。Windows SmartScreen が警告を表示することがあります。必要に応じて `.sha256` を確認してください。内蔵アップデーターはインストール前に検証します。

> 💡 内蔵ウィンドウを開けない場合（WebView2 や `Python.Runtime.dll` がブロックされている、ダウンロード後によくあります）、Stellio は別の Edge/Chrome ウィンドウで開き、閉じると終了します。内蔵ウィンドウを戻すには、zip を右クリック → プロパティ → **ブロックの解除**、そのあと展開し直してください。詳細は `data\stellio.log` にあります。

## macOS

`.dmg` を開き、Stellio を「アプリケーション」にドラッグします。お使いの Mac に合うファイルを選んでください：`arm64`（M1、M2、M3…）または `x86_64`（Intel）。ビルドは公証されていません。初回起動時は右クリック → **開く**。

> 画面が白いままの場合：ポート 5000 が macOS の「AirPlay レシーバー」に使われている可能性があります。その場合、Stellio は自動的に別の空きポートを選びます。[トラブルシューティング](ja-Troubleshooting) を参照してください。

## Linux（AppImage）

```bash
chmod +x Stellio-v*-x86_64.AppImage
./Stellio-v*-x86_64.AppImage
```
AppImage にはアップデート情報（`.zsync`）が含まれています。

## Raspberry Pi / Linux サーバー

**ヘッドレスサーバー**モード：Stellio はバックグラウンドで動作し、ブラウザから使います。詳細は [サーバー版](ja-Server-Edition) を参照してください。

```bash
curl -O https://raw.githubusercontent.com/stellio-app/stellio/main/install-pi.sh
chmod +x install-pi.sh
./install-pi.sh
```

## Proxmox VE

**Proxmox ホストのシェル**で：
```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/stellio-app/stellio/main/stellio-lxc.sh)"
```
詳細は [サーバー版](ja-Server-Edition) を参照してください。

## アップデート

- **デスクトップ**：Stellio は GitHub で新しいバージョンを検出し、`.zip` パッチを適用します（Windows、macOS、Linux で同じ仕組み）。ダッシュボードの「アップデート」ウィジェットからアップデート画面を開けます。
- **サーバー**：同じ自動アップデート、または `update-stellio`（LXC コンテナ）／`./install-pi.sh`（Raspberry Pi）。
- 各バージョンの初回起動時に、不足しているモジュール（PDF 見積、表計算のインポート、通知など）が自動でダウンロードされます。

# はじめに
{{img:library}}

左側のバーはアイコンの**レール**です。カテゴリをクリックすると右側に**パネル**が開き、選択後に閉じます。

{{img:sidebar-panel}}


## 1. 初回起動
Stellio は**ガイドツアー**と「はじめに」チェックリストを表示します。ツアーは設定からいつでもやり直せます。

## 2. アカウントを作成する
アカウントは**ローカル**です：パスワード + 復旧コード + 秘密の質問。パスワードのリセットは 100% ローカルで、メールもインターネットも不要です。

## 3. ソースを追加する
**ソース**は、モデルが入っているフォルダーまたは共有です：
- ローカルフォルダー、単一ファイル、**SMB** または **NFS** 共有；
- コンピューターで検出された 3D フォルダーは**候補として提案**され、ワンクリックで追加できます；
- ソースごとに、表示するファイルの種類を選べます。

その後 Stellio がファイルをスキャンし、バックグラウンドで 3D サムネイルを生成します。

## 4. プリンターを追加する（任意）
**プリンター**ページを開きます：ネットワーク検出が見つかった機器を提案します。[プリンター](ja-Printers) を参照してください。

## 5. スライサーを選ぶ
Stellio はインストール済みのスライサー（OrcaSlicer、Bambu Studio、PrusaSlicer、Cura など）を自動検出します。送信ボタンでファイルをスライサーで直接開けます。

## ダッシュボード
ホームには、進行中の印刷、在庫不足、最近の印刷、最近のファイルがまとまっています。**ウィジェット**（約 20 種類）はドラッグ＆ドロップで並べ替え、非表示にできます：現在の印刷、在庫不足、最新の S.O.S Print、提案、Stellio インスタンス、完了したプロジェクト、ギャラリー、見積など。

## ナビゲーション
左のバーは**細いレール**で、ホーム、ライブラリ、印刷、フィラメント、ツール、トラッキングが並びます。カテゴリをクリックするとその**パネル**が開き、選択後に閉じます。カテゴリ内のページの通知バッジはアイコンに**合算**されます。下部にはワークショップモード、ヘルプ、**アップデート**、設定があります。**プロジェクト**と**印刷済み**は「印刷」にあります。

## 毎日使うツール
- **コマンドパレット** `Ctrl+K`：移動、操作の実行、ファイル・タグ・スプール・プロファイルの検索。
- **通知センター**（ベル）：印刷完了、失敗、メンテナンス、在庫不足、スプールの乾燥。
- **フローティングウィジェット**：現在の印刷の進捗を表示し、すべてのページで見えます。
- **キーボードショートカット**：[設定とデータ](ja-Settings-and-Data) を参照。

# ステップバイステップガイド

Stellio のすべての機能について、**何のためにあり、どう使うか**を説明します。技術的な詳細は他のページにあります。ここでは実際に操作します。

> 💡 アプリのどこでも：`Ctrl+K` で**コマンドパレット**（移動、操作の実行、ファイル・タグ・スプールの検索）、`?` でショートカット一覧が開きます。

## Stellio の画面を知る

| メニュー | 用途 |
|---|---|
| **ダッシュボード** | 進行中の印刷、在庫不足、最近のファイル。ウィジェットは並べ替え可能。 |
| **ライブラリ** | すべての 3D モデル。サムネイル、タグ、フィルター、検索つき。 |
| **もうすぐ印刷** | 印刷待ちリスト（並べ替え可能）。 |
| **プロジェクト** | 1 つの造形物に複数のファイルをまとめる。 |
| **プリンター** | ライブ監視、送信、メンテナンス、消耗部品。 |
| **フィラメント在庫** | スプール、残量切れの予測、乾燥。 |
| **履歴** | 送信したすべての印刷。成功・失敗の評価つき。 |
| **ギャラリー** | 印刷物の写真。 |
| **統計** | 信頼性、消費量、形式、レポート。 |
| **管理** | コスト、顧客向け見積もり、注文、会計。 |
| **工房モード** | タブレットやスマートフォン向けの全画面表示。 |
| **S.O.S Print** | 印刷失敗のガイド付き診断。 |
| **ダウンロード** | Printables、MakerWorld、Thingiverse などからモデルを取得。 |
| **修復** | 壊れたメッシュを見つけて修復。 |
| **コンバーター** | ある 3D 形式から別の形式へ変換。 |
| **重複** | 重複ファイルを見つける。 |
| **ごみ箱** | 削除したものを復元。 |
| **設定** | 外観、スライサー、AI、バックアップ、リモートアクセス。 |

## ファイルを追加して見つける

1. **ソースを追加**をクリック（または `Ctrl+K` から「ソースを追加」）し、**フォルダー**、単体のファイル、または **SMB / NFS** 共有を選びます。パソコン内で見つかった 3D フォルダーが候補として表示されます。
2. Stellio はバックグラウンドでスキャンして **3D サムネイル**を作成します。アプリを使っている間、生成は一時停止します。
3. モデルを探すには、**検索**バーに入力するか、AI 検索で自然な文章（「ヘッドホンスタンド」）で説明します。
4. エクスプローラーから 3D ファイルをドラッグ＆ドロップすると、そのまま追加できます。

💡 アーカイブ（ZIP、RAR、7z、TAR）は展開せずに中身を見られます。

## タグ・お気に入り・フィルターで整理する

1. ファイルの **⋯** メニューを開くか、複数選択（`Shift+クリック` で範囲選択）して一括操作します。
2. 色付きの**タグ**を手動で追加するか、AI の提案に任せます。`T` でタグ管理を開きます。
3. 星をクリックしてモデルを**お気に入り**に（`F` でお気に入りを開く）。
4. **フィルター**（種類、サイズ、重量、印刷状況、「フィラメント在庫」）を組み合わせ、**保存**して再利用します。
5. 多数のファイルを改名するには、**一括リネーム**（検索/置換、接頭辞、接尾辞、連番）を使います。確定前にプレビューできます。

## 3D でモデルを確認・準備する

1. ファイルのサムネイルをクリックすると **3D ビューアー**が開きます（オフラインでも動作）。
2. 回転とズームができ、複数プレートの 3MF ではプレートを切り替えられます。
3. **造形可否の分析**（オーバーハング）を実行すると、Stellio が推奨の**向き**を提案します。
4. **自動配置**で、プリンターのベッド上に複数のパーツを並べます。
5. ビューアーから結果をスライサーに送信します。

## 壊れたメッシュを修復する

1. **修復**を開くと、穴や開いた辺のあるファイルが一覧表示されます（サムネイル作成時にバックグラウンドでも分析されます）。
2. ファイルを選んで**修復**を実行し、**修復前 / 修復後**を比較します。
3. ファイルはその場で修復され、念のため `.bak` の安全コピーが残ります。

## ファイルを変換する

1. **コンバーター**を開き、1 つ以上のファイル（STL、3MF、OBJ、PLY、AMF、STEP）を選びます。
2. 出力形式を選びます：STL、3MF、OBJ、PLY、OFF、GLB。
3. 必要に応じて**メッシュを自動修復**と**元のファイルを削除**にチェックを入れます。
4. 開始します。一括変換はいつでもキャンセルでき、変換済みのファイルは残ります。

## モデルを実寸大に拡大する（BigPrint）
BigPrint（**ツール**メニュー）は、モデルを好きなサイズ（1.8 m以上も可）に拡大し、ベッドに収まるパーツに分割します。パーツは中空化され、接合用ダボが付き、各パーツに番号が刻印されます。計算には Stellio に組み込まれたオープンソースエンジン [bigprint](https://github.com/PooterTF/bigprint)（AGPL-3.0、作者 Michael Christopher Stone）を使用します。

{{img:bigprint}}

1. モデルを選びます：**ライブラリから選択**、**ファイルを読み込む**、またはファイルの**アクション**メニューの**BigPrintに送る**ボタン（STL、3MF、OBJ、PLY）。
2. **最終サイズ**（高さ・幅・奥行き・拡大率）と**プリンター**（プリセット一覧またはカスタム寸法）を指定します。
3. **強度**（用途・素材・中空化・シェルの厚み）と**ダボ**を設定します。詳細オプション（上方向の軸・余白・スムージングなど）は折りたたまれています。
4. **プレビュー**をクリック：Stellio がパーツを分解表示し、フィラメント重量・見積もりコスト・パーツ一覧を表示します。計算はいつでもキャンセルできます。

{{img:bigprint-result}}

保存先（ライブラリのソース、サブフォルダー、フォルダー作成、ネットワーク共有も可）を選び、**印刷ファイルを保存**：STLパーツ、3MFプロジェクト、ダボ、レポート、プレビューが `<モデル名>_bigprint` フォルダーにコピーされます。

プレビュー後に設定を変えた場合は、保存前にもう一度プレビューを実行してください。

## 整理整頓：重複とごみ箱

1. **重複**を開くと、同一のファイルと**形状が近い**ファイル（同じモデルの改名・再エクスポート）がグループ化されます。
2. 残したいものを選び、他は削除します。
3. 誤って削除した？ `Ctrl+Z` で 5 分間は取り消せます。**ごみ箱**はそれより長く保管し、復元や完全削除ができます。

## ファイルをプロジェクトにまとめる

1. **プロジェクト**を開いて作成し、同じ造形物のファイル（本体、ふた、サポートなど）を追加します。
2. プロジェクトに追加した**複数プレート**の 3MF は、プレートごとの 3MF に分割されます（⋯ メニューの**プレートを分割**でも可能）。
3. 進捗（「進行中」/「完了」）を確認し、**プロジェクトコスト**をクリックすると全体の原価を計算できます。

## モデルをダウンロードする

1. **ダウンロード**を開き（または `Ctrl+N`）、モデルのリンク（Printables、MakerWorld、Thingiverse、Nexprint、Creality Cloud、Snapmaker Space）を貼り付けます。
2. 求められたアカウントを一度だけ接続します（[ダウンロード](ja-Downloads)を参照）。
3. 保存先の**ソース**を選びます。ファイルは**出典**（リンク、作者、ライセンス）つきで保存されます。
4. Stellio は毎日、モデルの**新バージョン**がないか確認します。**いいね一覧**と**自分の作品**で、接続済みアカウント上のモデルを見つけられます。

## プリンターを接続する

1. **プリンター → 追加**を開くと、**ネットワーク検出**が見つけた機器を提案します。見つからない場合は、種類、アドレス、アクセスキーを入力します。
2. **造形サイズ**（X、Y、Z）を入力します。大きすぎるパーツは送信前に Stellio が警告します。
3. 必要なら**このプリンターのスライサー**（1.0.8）を選びます。この機械ではそのスライサーが開きます。
4. 便利なオプションを有効にします：**タイムラプス**、**造形終了時の写真**、**AI 監視**、**スマートプラグ**（実際の消費電力）。

## ファイルをスライサーに送る

1. ライブラリまたはビューアーで**スライサーに送信**をクリックします。
2. ウィンドウで**見積もり**（重量、時間）を確認し、**プリンター**、**スプール**、**設定プロファイル**を選ぶか、「自動」のままにします。
3. **印刷前チェック**を読みます：乾燥が必要なスプール、研磨性フィラメント、サイズ超過、材料不足。
4. **送信**をクリックすると、そのプリンターのスライサー（または設定のスライサー）でファイルが開き、機械に紐づけたプロファイルが読み込まれます。指定した場合、スプールの使用量が差し引かれます。

💡 プロファイルをプリンターに紐づけるには、設定 → スライサーからインポートします。

## 次の印刷に備える：「もうすぐ印刷」

1. ファイルの **⋯** メニューで**もうすぐ印刷に追加**を選びます。
2. **もうすぐ印刷**を開き、ドラッグして**並べ替え**ます。
3. 項目をそのままスライサーに送るか、リストから外します。

## 印刷を見守る

1. プリンターのカードに、温度、進捗、**ライブカメラ**、現在のファイル名が表示されます。
2. **フローティングウィジェット**がすべてのページで進捗を表示します。
3. **ベル**が通知します（完了、失敗、メンテナンス、在庫不足）。**プッシュ通知**（ntfy、Gotify、Pushover、Telegram、Discord、Slack、webhook）を有効にすると、ウィンドウを閉じていても届きます。
4. 100% になると、Stellio が**終了時の写真**を撮ります。ワンクリックで*成功*か*失敗*かを記録できます。**タイムラプス**は自動で作成されます。

## 評価・再印刷・写真の確認

1. **履歴**を開き、プラットフォーム、結果、日付で絞り込みます。
2. 各印刷を**成功**または**失敗**で評価します。推奨や統計に反映されます。
3. **ファイルを見る**、または前回と同じ設定で**再印刷**します。
4. 写真は**ギャラリー**で見られます。**自分の G-code** には、ファイルに紐づく G-code が保存され、**スライサーで開く**ボタンがあります。

## スプールを管理する

1. **フィラメント在庫**を開き、スプールを手動で追加（または Excel/CSV をインポート）し、**Spoolman**、**TigerTag**、**OpenPrintTag** を連携するか、**Open Filament Database** でスプールを検索します。
2. スライサーへ送信するときにスプールを選ぶと、Stellio が消費量を**差し引き**、残量が足りるか確認します。
3. **計量と予測**でスプールを量ると、Stellio が**残量切れの日**を見積もり、近づくと知らせます。
4. スプールの**乾燥**を記録して状態を追跡し、**買い足す**でメーカーのショップを開きます。

## コストを計算して見積書を作る

1. ファイル（**コスト**）またはプロジェクト（**プロジェクトコスト**）から計算機を開きます。
2. 材料、電気、**機械の消耗**、**固定費**、**利益率**、**数量**を確認すると、単価と合計が表示されます。
3. **見積書を生成（PDF）**をクリックし、顧客と品名を入力します。PDF は保存され、**見積書**ウィジェットから確認できます。
4. 既定の利益率は**設定 → 印刷の価格設定**で決めます。

## 注文・顧客・請求書を管理する

1. 設定で「コスト・見積もり・請求機能を有効にする」をオンにすると、**管理**画面が表示されます。
2. 見積書を**追跡リンク**つきで顧客に送ります。顧客はオンラインで承認または辞退でき、承認すると印刷タスクが作られます。**Stellio は支払いを一切処理しません。**
3. **注文キュー**、支払い、前受金の請求書、クレジットノートを確認します。**スマート割り当て**は適したプリンターを提案しますが、印刷を勝手に開始することはありません。
4. 毎月、**会計**データ（CSV と PDF を含む ZIP）をエクスポートします。

## 生産を計画する（計画と生産能力）
**計画**ページ（**印刷**メニュー）は、プリンターごとに各注文の完了予定日を算出し、利用可能な能力と要求負荷を比べ、過負荷や遅延が起きる前にお知らせします。

{{img:planning}}

1. **注文**で各注文の**1個あたりの時間**（時間単位）を入力します。見積から作られた注文は原価計算から引き継がれます。時間のない注文はスケジュールされず、ページ上部に表示されます（そこで直接入力できます）。
2. 各注文の**プリンター**を選びます（未選択の場合、Stellio が最も早く空く機械に仮に割り当てます）。**納期**も指定します。
3. **計画**を開くと、プリンターごとの注文の並びがバーで表示されます（赤＝遅延見込み、オレンジ＝余裕1日未満）。各機械の**負荷率**も確認できます。印刷中のものは、プリンターから読み取った残り時間で考慮されます。
4. **期間**（7・14・30日）を設定します。上部のカードに、能力・負荷・遅延見込み・直近90日の**納期遵守率**がまとまっています。

**プリンターの生産能力**：機械ごとに1日に印刷できる時間と稼働日を指定します（既定は16時間・毎日）。チェックを外すとその機械は計画から除外されます。

注文が納期を過ぎそうなとき、またはプリンターが過負荷のとき、Stellio が通知します（注文ごとに1日1回）。

計算は意図的に単純です。入力した時間をもとに、納期順に注文を並べます。素材交換や故障は考慮しません。

## 最良の組み合わせを見つける（トレーサビリティ）
**トレーサビリティ**ページ（**印刷**メニュー）は、各印刷を使用した**モデルの正確なバージョン**と**スライサープロファイル**に紐づけ、モデルごとに最も成功率の高い組み合わせを表示します。

{{img:trace}}

1. いつも通り Stellio から印刷します。印刷は自動的にモデルへ紐づきます。前回のバージョンからファイルが変わっている場合は「印刷前」バージョンを保存するため、関連付けは常に正確です。
2. 印刷後、履歴で**結果を評価**します（成功・失敗・一部）。成功率はこの評価から算出されます。
3. **トレーサビリティ**を開くと、モデルごとに1行で、バージョンと**最良の組み合わせ**（バージョン＋プロファイル、評価済み印刷での成功数）が表示されます。クリックすると**モデルのバージョン**が開きます。
4. **モデルのバージョン**では、各バージョンの成功・失敗数と成功率が表示され、表は**バージョン×プロファイル**で集計されます。

{{img:trace_versions}}

順位は少ない標本に惑わされません。9回中8回成功は1回中1回成功より上位です。最良の組み合わせは、評価済み印刷が2回以上でバージョンが判明している場合にのみ表示されます。

追跡は v1.1.6 から始まります。過去の印刷は再構築されません。

## プリンターのメンテナンス

1. プリンターのカードで**メンテナンス**を開き、**ブランド**を選ぶと、推奨タスクが表示されます。
2. 追跡に追加すると、印刷時間と経過日数に応じて「要対応」になります。
3. **消耗部品**（ノズル、プレート、ベルト）をアラートの閾値つきで、また**キャリブレーション**をフィラメントごとに記録します。

## 失敗を診断する：S.O.S Print と AI

1. **S.O.S Print** を開き、問題を説明します（写真も添付可能）。
2. 質問に 1 つずつ答えます（**回数の制限なし**）。Stellio は原因が見つかるまで候補を絞り込み（必要なら新しい候補を追加）、**最終診断**を出します。解決しなければ「まだ解決しない」と答えると調査が続きます。
3. ローカル AI を使うには、[Ollama](https://ollama.com/) をインストールし、**設定 → 人工知能**で設定します。**失敗の監視**は警告しますが、印刷を止めることは決してありません。

## スマートフォンやリモートで Stellio を使う

1. **設定 → モバイルアクセス**で **QR コード**を読み取ると、ライブラリがスマートフォンで開きます（アプリのようにインストール可能）。
2. **Android** アプリは、専用の QR コードを読み取ります。
3. 外出先では、**リモートアクセス**（Cloudflare Tunnel またはカスタムアドレス）を有効にするか、一時的な**共有リンク**を作成します。
4. **ゲストアカウント**で閲覧専用の共有ができます。

## バックアップと復元

1. **設定 → バックアップとデータ**を開き、データを**エクスポート**します（.zip）。
2. **自動バックアップ**をスケジュールします。
3. 復元するには、.zip ファイルを**インポート**します。Stellio のアップデートがデータに触れることはありません。

## ソースとサムネイル
- 複数のソース：ローカルフォルダー、ファイル、SMB/NFS 共有。
- **3D サムネイルを自動生成**（PyRender、または CPU のフォールバックレンダラー）。ホバーで拡大プレビュー。

## 整理する
- 色付きの**タグ**。AI による自動タグ付けにも対応。複数ファイルにワンクリックでタグ付け。
- **お気に入り**、詳細フィルター（種類、サイズ、重量、印刷状況）、**保存済みフィルター**。 アクセス：**F** キー、ダッシュボードのウィジェット、各ファイルの星（星を外すとお気に入り表示からすぐに消えます）。
- 状況フィルター：「スライサーへ送信済み」「印刷済み」「成功済み」「失敗済み」。
- **「フィラメント在庫」フィルター**：手持ちのスプールで印刷できるファイルだけを表示。
- 並べ替え、検索、フィルターはアプリを開き直しても**記憶**されます。
- **「近日印刷」**キュー。並べ替え可能で、スライサーへ送信できます。
- **一括リネーム**（検索/置換、接頭辞、接尾辞、連番）。プレビュー付き。
- **削除の取り消し**（`Ctrl+Z`）：5 分間の一時ごみ箱による。タグ、プロジェクト、ソースにも対応。
- サムネイルの周りの**緑／赤のハロー**：印刷に成功したファイルは緑、失敗したものは赤（ギャラリー表示・詳細表示）。
- **印刷済み**（ファイルの ⋯ メニュー）：他の場所で行った印刷を手動で記録します。プリンター、設定（スライサーのプロファイル）、スプールを選び、**成功**または**失敗**を押します。ファイルは「成功済み」／「失敗済み」フィルターに入り、右クリックの詳細にもプリンター・設定・スプールが表示されます。
- **「印刷済み」ページ**（印刷パネル）：印刷した、または「印刷済み」にしたすべてのファイルを、ライブラリと同じサムネイルとハローで表示し、検索と成功 / 失敗フィルターを備えます。サムネイルにマウスを重ねると**赤い×**が表示されます（スマートフォンでは1回タップで表示、もう1回タップでファイルを開きます）。確認後にリストから外すと、ファイルは「未印刷」に戻ります。ファイル情報の**削除**ボタンでも同じ操作ができます。ホームには同名のウィジェットもあります。
- 高速選択：`Shift+クリック` で範囲選択、矢印キー + `Enter`。
- **重複検出**（完全一致および形状が近いもの）。
- **モデルの出典**：元リンク、作者、ライセンス、メモ、ダウンロード日。
- エクスプローラーから 3D ファイルを**ドラッグ＆ドロップ**。ブラウザ経由でも可能。

## 3D ビューアーとツール
- **3D ビューアー**（Three.js、オフラインで動作）。プレート間の移動に対応。
- **ベッド自動配置**（rectpack、または shapely による実シルエット）。
- **BigPrint**（**ツール**メニュー）：モデルを好きなサイズに拡大し、ダボ付きの番号入りパーツに分割。分解表示の3Dプレビューとフィラメント・コストの見積もり付き（オープンソースエンジン bigprint）。

- **選択バー**：すべてのボタンが同じサイズで1行に収まります（小さな画面ではアイコンのみ、名前はツールチップに表示）。
- **メッシュ修復**（trimesh + pymeshfix）。修復前後の比較付き。
- **コンバーター** STL ↔ 3MF ↔ OBJ。
- **造形可能性の分析**（オーバーハング）と**推奨向き**。
- **整合性チェック**（破損または欠落したファイル）。
- 詳細な**統計**（形式、プラットフォーム、プロファイルの信頼性）。

## 大きなモデル
STL は読み込むとメモリ上でサイズの約 12 倍を占めます。しきい値（256 MB、空きメモリが十分あれば最大 1 GB）を超えると、Stellio は全体を読み込まなくなります：ストリーミング解析（バイナリとテキストの STL）、簡略化版（約 300,000 三角形）でのサムネイルとビューア、書き込み操作（修復、変換など）は分かりやすいメッセージとともに拒否されます。
それでも作業したい場合：右クリック › **軽量版を作成**。Stellio は元のファイルの隣に簡略化したコピー（`名前 (軽量).stl`）を書き込み、元のファイルは変更しません。コピーは閲覧・計測・修復・インデックス作成用で、フル解像度での印刷には向きません。サイズが理由で修復が拒否されたときにも提案され、ローカルの STL ファイルのみが対象です。スライサー（OrcaSlicer など）から書き出した STL や 3MF は、はるかに軽いことが多いです。
高度なワークショップでは、各「モデルのパス」欄に**ライブラリから選択**があります：ソース、検索、形式フィルター（STL、3MF…）、サムネイル、ページ分割。

**アシスト付き生産（1.1.8）。** ファイルのメニューの**アシスト付き生産**は、最適なプリンター（空き、材料が合う、待ちが短い）と Intelligence 推奨のスライサープロファイルを提案し、ファイル（スライスが必要な生モデル、プリンターに合わない形式）、プリンター（オフライン、使用中）、消耗品（フィラメントまたはレジンが十分か）を確認します。**承認なしには何も送信されません**。*この選択を承認*をクリックするまで、サーバーが送信を拒否します。そのあと Stellio はファイルをプリンターに送りますが、**遠隔では印刷を開始しません**（機械側で開始します）。印刷の終了を検知して履歴に記録し、機械が通知しない場合は結果を自分で入力します。**採用した**推奨とその結果は Intelligence のランキングを補正します。3 回以上採用して成功率が 40% 未満のプロファイルは降格、80% 以上で優先されます（統計ページの*アシスト付き生産*カード）。

## 印刷中
- **スマートプラグ**（Shelly、Tasmota、Home Assistant）：Stellio がワット数を読み取り、実際の消費電力（kWh）とコストを記録します。
- 印刷後に記録される**実際のフィラメント消費量**。
- **印刷終了時の写真**は、印刷が **100%** に達した時点（造形物がまだベッドにある状態）で撮影され、*成功/失敗*を評価するための 1 枚だけです。
- **AI による失敗の監視**（ビジョン対応 Ollama、100% ローカル）：スパゲッティや剥がれを検知して通知し、**自動停止は決して行いません**。
- 自動**タイムラプス**（カメラ → MP4 動画、ffmpeg が必要）。
- 閲覧専用の**状況共有リンク**。

## カメラによる失敗検出（Obico）

# フィラメント

## レジン
サイドバーのカテゴリは **素材** という名前になり、**フィラメント**（スプール在庫）と **レジン** の 2 ページをまとめています。レジン在庫は**手動**です。ボトル（名前・ブランド・種類・色・容量・残量・価格・保管場所・メモ）を登録し、「使用」ボタンで ml 単位の使用量を差し引きます。1.1.8 から **自動消費**（レジンページの下部）があります。各レジンプリンターの**使用中ボトル**を選ぶと、印刷終了時に Stellio がそのボトルから使用量を差し引きます。量は `.sl1` ファイル（`usedMaterial` フィールド）から読み取り、なければライブラリ内の同名モデルから**推定**（閉じたメッシュの体積＋サポートやロス分 15%）して推定と表示します。信頼できる値がなければ**何も差し引かず**、通知でお知らせします。失敗した印刷は、進捗が分かる場合に印刷済みの分だけ差し引きます。差し引きは履歴に残り**取り消し**できます。残量はゼロを下回りません。

フィラメントと同様に、**「要注文」** リマインドはレジンでも使えます。レジン（ブランド + 名前 + 色、全ボトル合計）の残量がページで設定したしきい値（既定 200 ml、0 = 無効）を下回るか、ボトルで「要注文」にチェックを入れるとリストに入ります。ダッシュボードの「要注文」ウィジェットにも表示されます。**注文** はショップへの検索リンクを開き（レジンの在庫は自動確認されません）、**注文済み** はリマインドを 14 日延期します。

# 人工知能

> ⚠️ AI は 100％ 信頼できるわけではなく、間違えることがあります（タグ、説明、S.O.S Print の診断など）。回答は確認すべき手がかりとして扱い、確実なものとは考えないでください。

## ローカル AI（Ollama）
既定では、AI は [Ollama](https://ollama.com/) で **100% ローカル**に動作します。無効にもできます。

機能：
- モデルの**自動タグ付け**と**説明文**；
- 自然言語の**セマンティック検索**；
- **造形可能性の分析**と**推奨向き**；
- **スライサープロファイルの推薦**（形状 + 成功履歴）；
- スライス前の**印刷時間の推定**；
- **失敗の監視**（ビジョンモデル）。

Ollama サーバーのアドレスは設定で指定します（`ollama_url`）：より高性能なリモートマシンを指定できます（Raspberry Pi で便利）。

## オンライン AI（サーバー版、任意）
Ollama の代わりに、**Claude**（Anthropic）、**ChatGPT**（OpenAI）、**Gemini**（Google）を**ご自身の API キー**で使えます（設定 → 人工知能）。
- キーはサーバー上で暗号化され、ブラウザには返されません。
- リクエスト（ファイル名、タグ、説明、S.O.S Print の写真）は選択したプロバイダーに送られ、お客様のキーに課金されます。
- 既定は引き続き Ollama です。

## S.O.S Print
印刷失敗の**適応型**診断：
1. 問題を説明します（各ステップで写真も添付可能）。必要なら使用した設定（温度、速度、リトラクションなど）も入力します。 **速度**は選択したスライサープロファイルから読み取られます（手入力も可）。不足していれば AI が質問します。 **多色**印刷では、AI が**プライムタワー**（剥がれ・倒壊・造形物への落下・色混じり）に注目して質問し、タワー幅はプロファイルから読み取ります。 最初のステップと各回答のあとで、AI は**可能性順の仮説**（％）を、理由や簡単な確認方法とともに表示します。
2. Stellio は**一度に 1 つ**、回数の制限なく質問し、仮説のリストをリアルタイムで絞り込みます（最初の候補が除外されたら新しい候補を追加）。
3. **最終診断**を提示します。

**質問3**から、**結論を出して解決策を提案**ボタンで最も可能性の高い原因を提示し、「この診断で問題は解決しましたか？」と確認します（**はい、解決しました** / **いいえ、調査を続ける**）。**調査を中止**ボタンでいつでも中断できます。

会話は保存されます：再び開く、または解決済みにできます。

> ℹ️ 履歴で評価した「成功 / 失敗」の結果は、推薦の精度を高めます。

## 印刷コストの計算
材料、電気代、機械の摩耗（時間あたり）、固定費、利益率（%）、数量：単価と合計を 1 円単位まで正確に計算します。

- **完成品の在庫**：アラートのしきい値と補充（タスクを手動または自動で作成）。

# サーバー版

**サーバー版**は、Linux（Raspberry Pi、VM、LXC、Docker）上、または `STELLIO_HEADLESS=1` を指定したときに有効になります。Windows と macOS はデスクトップアプリのままです。Stellio はバックグラウンドで動作し、ブラウザから使います：`http://<ip>:5000`。

## Raspberry Pi / Linux
要件：Raspberry Pi 4 または 5 を推奨、**64 ビット**の Raspberry Pi OS。

`install-pi.sh` は、システム依存パッケージ（`ffmpeg`、`unrar`、3D レンダリングライブラリ）、専用の Python 環境、起動時に開始してクラッシュ時に再起動する `stellio` **systemd サービス**をインストールします。

```bash
sudo systemctl status stellio
sudo systemctl restart stellio
sudo journalctl -u stellio -f
```
メモリが少ない場合は、Python 依存パッケージのインストールが失敗するときにスワップを増やし、スクリプトを再実行してください。

## Proxmox VE（LXC コンテナ）
`stellio-lxc.sh` スクリプトは**既定**または**詳細**設定（CTID、コア数、RAM、ディスク、ブリッジ、VLAN、DHCP または固定 IP、ストレージ、マウントするホストフォルダー）を提示し、続いて：
- **非特権 Debian 12** コンテナを作成します（2 コア、RAM 2 GB、ディスク 32 GB、起動時に自動開始）；
- `install-pi.sh` で Stellio をインストールします；
- アドレス `http://<コンテナのIP>:5000` と root パスワードを表示します。

```bash
pct exec <CTID> -- update-stellio              # 更新
pct exec <CTID> -- journalctl -u stellio -f    # ログ
```
- **非対話モード**：変数 `var_mode=default var_cpu=4 var_ram=4096 var_disk=16 var_ip=192.168.1.50/24 var_gw=192.168.1.1`（一覧はスクリプトの先頭）。
- **ストレージ**：`var_choose_storage=1`、`var_storage`、`var_template_storage`。
- スクリプトの**言語**：`var_lang=ja`（fr、en、de、es、pt、it、zh、ja）。
- **ソース**：このコンテナでは **SMB/NFS** 共有のみが提示されます。`var_mount=/host:/mnt/models` を指定すると「ローカルフォルダー」も許可されます。設定：`/etc/systemd/system/stellio.service.d/sources.conf`（`STELLIO_ALLOWED_SOURCE_TYPES`）。

## 保護機能（1.0.7）
`install-pi.sh` は次を設定します：
- **毎分のチェック**（`stellio-watchdog`）：Stellio が応答しなくなったら再起動（チェック 3 回連続失敗、起動後 3 分の猶予）、停止していれば起動、IP アドレスを失ったらネットワークを再起動、ディスクの空きが 300 MB 未満ならログと apt キャッシュを削除；
- 再起動を**決して諦めない**サービス；
- **CPU 75%**、**RAM 75%（減速）/ 85%（ハードリミット）**の上限、低優先度、メモリ不足時は Stellio を最初に犠牲にする；
- ログを **100 MB** に制限。

チェックの介入記録：`journalctl -t stellio-watchdog`。既存のコンテナは `update-stellio` ですべてを受け取れます。

## サーバー版の特徴
- ☁️ 任意の**オンライン AI**（[人工知能](ja-AI) を参照）。
- 📥 **スライサープロファイル**：Stellio は PC 上のスライサーを見ることができず、スライサーのクラウド（Orca Cloud、Bambu Cloud など）にも接続しません。プロファイルをエクスポートし（OrcaSlicer：ファイル → エクスポート → プリセットバンドルをエクスポート）、*設定 → マイスライサープロファイル* でインポートするか、**監視対象のプロファイルフォルダー**（Syncthing、ネットワーク共有、scp など）を使ってください。
- 🐯 **TigerTag**：メールとパスワードによる公式サインイン。Google アカウントの場合は、まず TigerTag アプリの「パスワードを忘れた場合」でパスワードを設定してください。代替手段：TigerTag Studio のデータフォルダーをサーバーにコピー。
- アップデート後、ブラウザは自動的に再読み込みされます。

## サーバー専用の機能（1.1.7）
これらの機能はデスクトップアプリにはなく、該当するルートは「サーバー版専用」と応答します：

# トラブルシューティング

まずは**診断**（設定 → 診断）をエクスポートし、報告用に保管してください。

## 起動時に画面が白いまま（macOS）
ポート **5000** は *AirPlay レシーバー* に使われていることがよくあります（Safari で 403）。Stellio は現在、空きポート（5001–5030）を**自動的に**選びます。それでも解決しない場合：システム設定 → 一般 → AirDrop とHandoff → *AirPlay レシーバー* をオフにします。ログ：`~/.stellio/stellio.log`（通常のレベルでは空です：デバッグモードを有効にしてください）。

## LXC コンテナに接続できなくなった
Proxmox のシェルから：
1. `pct status <CTID>`。停止していれば `pct start <CTID>`。
2. `pvesm status`：**ストレージが満杯**？ ストレージを共有している場合に最も多い原因です。
3. `pct exec <CTID> -- free -m` と `dmesg -T | grep -i "oom\|killed process"`：メモリ不足。
4. `pct exec <CTID> -- ip -4 a`：DHCP の IP が変わっていませんか？ ルーターで予約してください。
5. `pct exec <CTID> -- systemctl status stellio` と `journalctl -u stellio -n 100`。

1.0.7 以降は、自動監視が一般的なケースに対処します。`journalctl -t stellio-watchdog` を参照してください。

## サムネイルが遅い、または表示されない
- *設定 → サムネイル性能* を選びます：小さなマシンでは**エコ**。
- 非常に重いファイルは、タイムアウト後に代替サムネイルのままになります。
- アプリを使っている間は生成が一時停止します。これは正常です。

## プリンターが検出されない
- 同じネットワークにあるか確認してください（VLAN、ゲスト Wi-Fi）。
- IP アドレスとキーを使って手動で追加してください。
- Bambu Lab：LAN モードを有効にします。Klipper：Moonraker API に到達できる必要があります。

## 印刷終了時の写真がない
プリンターで*印刷終了時の写真*のチェックボックスを有効にし（AI 監視やスマートプラグと同様）、カメラが応答しているか確認してください。

## 「モジュールが見つかりません」
各バージョンの初回起動時に、Stellio は不足しているモジュールをダウンロードします。インターネット接続を確認してください。必要がない限り `STELLIO_NO_AUTO_INSTALL` は設定しないでください。

インストーラーは署名されていません。`.sha256` を確認してから、*詳細情報 → 実行* (Windows)、または右クリック → *開く* (macOS) を選びます。

# プラグイン

プラグインは、Stellio のイベント（印刷完了、印刷失敗、注文の遅延、プリンターの過負荷）に反応する小さな Python プログラムです。通知の送信、スプレッドシートへの書き込み、ランプの点灯などに使えます。プラグインは作者が **GitHub** で公開し、Stellio は **プラグイン › カタログ** メニューに**公開カタログ**（ロゴ + 説明）を表示します。ワンクリックでインストールできます。

各プラグインにはバッジが付きます。`stellio-app/stellio-plugins` リポジトリで公開されているものは**公式**、それ以外の場所で公開されているもの（または .zip からインストールしたもの）は**コミュニティ**です。バッジはアーカイブの実際のアドレスから Stellio が判定します。コミュニティのプラグインは必ず権限とコードを確認してください。

**プラグインのセキュリティ（1.1.8）。** インストール前に Stellio は**コードを監査**します（静的解析：宣言のないネットワーク利用、プロセス起動、動的コード、バイナリなど）。ブロックすべき検出があると、リスクを明示的に承認しない限りインストールを拒否します。カタログとプラグインは **Ed25519 で署名**できます。信頼できる鍵を設定すると、無効な署名、署名のない公式プラグイン、署名済みプラグインの未署名の更新は拒否されます（鍵が未設定のときは SHA-256 チェックサムだけが保護で、プラグイン画面にもそう表示されます）。**Linux** ではカーネルが各プラグインをさらに制限します：ファイルは読み取り専用（書き込みは `data/` フォルダのみ）、`network` 権限がなければネットワーク不可。**Windows と macOS ではこの制限は適用されません**：権限は宣言的なままで、プラグイン画面に表示されます。署名は出所を証明するもので、無害であることの証明ではありません。監査は隠されたコードを見逃すことがあります。必ずコードを読んでください。

**内蔵プラグイン。** Stellio の一部の機能は内蔵プラグインとして提供されます（BigPrint、レジン、USB プリンター、タイムラプス、ファイルツール、プレートスタジオ、プッシュ通知、Webhook、定期サマリー、MQTT / Home Assistant、Obico、共有と同期、Spoolman、AI プロバイダーと AI アシスタント、Stellio Pro）。アプリに含まれていますが、有効にした場合にのみ読み込まれます（プラグインページの「内蔵プラグイン」セクション。変更は再起動後に反映されます）。**以前のバージョンからの更新：何もする必要はありません。** 1.1.7 の初回起動時に、使用していたプラグイン（たとえば有効な MQTT、USB プリンター、Webhook、タイムラプス）が自動的に有効になり、設定はそのまま保持されます。設定のないツール（BigPrint、ファイルツール、プレートスタジオ）はそのまま残ります。新規インストールではどれも有効になりません。プラグインを無効にしても設定は削除されません。 他の内蔵プラグイン：共有と同期、Spoolman、AI プロバイダーごとのプラグインと AI アシスタント（すべての AI 機能を有効化）、**Stellio Pro**（顧客、見積、請求書、注文、会計、電力料金、計画、材料所要量、部品在庫）：有効にしたときだけ各ページとボタンが追加されます。

## プラグインを使う
1. **プラグイン › カタログ** を開きます（オーナーアカウントのみ）。
2. カタログを見て **インストール** をクリックします。Stellio がアーカイブをダウンロードし、SHA-256 チェックサムを検証します。
3. 要求された**権限**を読み、承認します。プラグインは**無効**の状態でインストールされます。
4. 必要に応じて設定を入力し、有効にして **テスト** をクリックすると、テストイベントで実行できます。実行ログに出力とエラーが表示されます。

ローカルの `.zip` アーカイブ（開発中のプラグイン）をインストールしたり、カタログの取得元を別のカタログの URL に変更したりすることもできます。

## プラグインを作る
### 1. 構成
プラグインは、`plugin.json` ファイルと Python スクリプトを含むフラットなフォルダーです。
```
mon-plugin/
├── plugin.json     マニフェスト（必須）
├── main.py         エントリーポイント（名前は自由、"entry" で指定）
└── ...             その他のファイル：最大 100 個、展開後 8 MB
```

### 2. マニフェスト plugin.json
```json
{
  "id": "mon-plugin",
  "name": "Mon plugin",
  "version": "1.0.0",
  "api": 1,
  "description": "Écrit une ligne à chaque impression terminée.",
  "author": "Votre nom",
  "entry": "main.py",
  "events": ["print.finished", "print.failed"],
  "permissions": ["events"]
}
```
| フィールド | 役割 |
|---|---|
| `id` | 一意の識別子：小文字、数字、`-` または `_`、2〜40 文字 |
| `name`、`description`、`author` | Stellio に表示されるテキスト |
| `version` | 数値形式（例：`1.2.0`）。更新の検出に使います |
| `api` | プラグイン API のバージョン：`1` |
| `entry` | ルートにある Python スクリプト（既定は `main.py`） |
| `events` | 受け取るイベント |
| `permissions` | 要求する権限 |
| `ui` | Stellio 内に表示するページ：`title`、`icon`（Font Awesome）、`entry`（`.html` ファイル） |

### 3. イベントと権限
| イベント | 発生するタイミング |
|---|---|
| `print.finished` | 印刷が完了したとき |
| `print.failed` | 印刷が失敗したとき |
| `order.late` | 注文が期限を過ぎたとき |
| `printer.overload` | プリンターが過負荷のとき |

| 権限 | 効果 |
|---|---|
| `events` | イベントを受信（`events` を宣言する場合は必須） |
| `api:read` | Stellio の公開 API でデータを読み取る |
| `api:write` | 公開 API でデータを変更する |
| `network` | 情報用：プラグインがインターネットにアクセスする |
| `ui` | プラグインのページをプラグインメニューに表示する |

### 4. スクリプト
Stellio は別プロセスで `python -I main.py <イベント>` を実行し、標準入力に JSON `{"event": "...", "data": {...}}` を送ります。`-I`（分離）モードではプラグインのフォルダーが Python のパスに追加されません。プラグイン内のファイルをインポートするには、そのパスを自分で追加してください。標準出力はログに記録されます。
```python
import json, os, sys

payload = json.loads(sys.stdin.read() or "{}")
event, data = payload.get("event", ""), payload.get("data", {})
config = json.loads(os.environ.get("STELLIO_PLUGIN_CONFIG") or "{}")

print(f"{event}: {data.get('file_name') or data.get('printer') or '-'}")
```
Stellio を操作する場合（`api:*` 権限）、スクリプトには `STELLIO_API_URL` と `STELLIO_API_TOKEN`（プラグイン設定の `api_url` と `token` キー）が渡されます。Python SDK `stellio_sdk.py`（リポジトリの `sdk/python` フォルダー）は `plugin_event()`、`plugin_config()` とすぐ使えるクライアントを提供します。プラグインにコピーし、インポートの前に `sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))` を追加してください。完全な例は `sdk/examples/hello-plugin` にあります。

制限：1 回の実行は 10 秒、メモリは 512 MB、環境は最小限（`STELLIO_*` 変数と `PATH` のみ）。Stellio を実行するマシンに Python 3 がインストールされている必要があります。設定はキーと値のペア（テキスト、数値、真偽値）のリストで、最大 4000 文字です。

### 5. テスト
フォルダーの**中身**を `mon-plugin.zip`（最大 2 MB）に圧縮し、**プラグイン › カタログ** からインストール（ローカルアーカイブ）し、権限を承認して有効にし、**テスト** を使います。ログを読んで問題を修正してください。

## ページを持つプラグイン：G-code ビューアーの例

プラグインは Stellio 内に**独自のページ**を表示することもできます。その場合、サイドバーの **プラグイン** メニューの「カタログ」の下、「インストール済み」リストに表示され、クリックするとそのページが開きます。例 `sdk/examples/gcode-viewer` は 3D G-code ビューアーで、3D 表示（回転・ズーム）、レイヤー範囲、移動の再生、種類・速度・流量による色分け、非押出し移動とリトラクションを備え、8 言語に対応しています。

```json
{
  "id": "gcode-viewer",
  "name": "G-code viewer",
  "version": "1.0.0",
  "api": 1,
  "description": "Shows your archived G-code files layer by layer.",
  "author": "Stellio",
  "permissions": ["ui", "api:read"],
  "ui": {
    "title": "G-code viewer",
    "icon": "fa-layer-group",
    "entry": "viewer.html"
  }
}
```

- ページは**単一の自己完結した HTML ファイル**（CSS と JavaScript を内包し、画像は `data:`）で、最大 1 MB です。イベントを使わない場合、Python スクリプトは不要です。
- ページは**分離された**フレームに表示され、ネットワーク、Cookie、Stellio の他の部分にはアクセスできません。
- Stellio のデータは `window.stellio.api(パス)` で読み取ります。読み取り専用（GET）で、`api:read` 権限が必須です。結果は JSON、第 2 引数に `'text'` を指定するとテキストです。設定、アカウント、セキュリティ、プラグインにはアクセスできません。
- テーマは CSS 変数 `--st-bg`、`--st-panel`、`--st-card`、`--st-text`、`--st-muted`、`--st-border`、`--st-accent`、`--st-success`、`--st-warning`、`--st-danger` で、言語は `window.stellio.lang` で提供されます。

```js
document.addEventListener('stellio-ready', async () => {
  const list = await window.stellio.api('/api/gcodes?limit=50');
  const id = list.gcodes[0].id;
  const text = await window.stellio.api('/api/projects/gcodes/' + id + '/download', 'text');
});
```

試すには：`gcode-viewer` フォルダーの中身を圧縮し、**プラグイン › カタログ** からインストールし、権限を承認して有効にし、**プラグイン** メニューから開きます。保存済みの G-code が少なくとも 1 つ必要です（ファイルの詳細またはプロジェクト）。無効のプラグインはリストでグレー表示になります。

## GitHub で公開する
1. コード、`README`、ライセンスを含む公開リポジトリをプラグイン用に作成します。
2. バージョンごとに GitHub の **release** を作成し、アーカイブ `mon-plugin-1.0.0.zip` を添付します。

sha256sum mon-plugin-1.0.0.zip

## Stellio カタログに掲載する
公式カタログは、リポジトリ `stellio-app/stellio-plugins` の `catalog.json` ファイルです。**Pull Request** でプラグインを追加します。

1. リポジトリ `stellio-app/stellio-plugins` をフォークします。
2. `catalog.json` にプラグインのエントリを追加します。
```json
{
  "id": "mon-plugin",
  "name": "Mon plugin",
  "version": "1.0.0",
  "description": {"fr": "Écrit une ligne à chaque impression terminée.", "en": "Writes a line when a print finishes."},
  "author": "Votre nom",
  "url": "https://github.com/vous/mon-plugin/releases/download/v1.0.0/mon-plugin-1.0.0.zip",
  "sha256": "64 caractères hexadécimaux",
  "permissions": ["events"],
  "logo": "https://raw.githubusercontent.com/vous/mon-plugin/main/logo.png",
  "homepage": "https://github.com/vous/mon-plugin"
}
```
3. Pull Request を開きます。自動チェックがリンク、SHA-256 チェックサム、ロゴを確認し、その後 Stellio チームがプラグインをレビューします。

| フィールド | ルール |
|---|---|
| `description` | 短く（約 140 文字）。単一のテキスト、または言語ごとのテキスト（`fr`、`en`、`de`、`es`、`pt`、`it`、`zh`、`ja`） |
| `url` | アーカイブへの `https` 直接リンク。`sha256` は完全に一致する必要があります |
| `logo` | `https`、PNG・JPEG・WebP、最大 200 KB、理想は 128 × 128（SVG は不可） |
| `homepage` | プラグインのページへの `https` リンク（任意） |
| `permissions` | マニフェストの権限と一致させる |

**更新**：新しい release を公開し、`version`、`url`、`sha256` を変更する Pull Request を開きます。新バージョンが追加の権限を要求する場合、ユーザー側ではそれを承認するまでプラグインが無効になります。設定は保持されます。

## 管理と監督対象インスタンス
**管理**プラグイン（デフォルトで有効）は、**ゲストアカウントとそのロール**、チーム、セッション、監査ログ、**インスタンス**を 1 ページ（管理 › 管理）にまとめます。

監督対象インスタンスは他を監督できず、プライマリインスタンスは監督されません。その他の設定はローカルで変更できます。
