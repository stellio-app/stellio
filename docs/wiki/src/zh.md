# 安装

| 平台 | 文件 / 方式 | 模式 |
|---|---|---|
| 🪟 Windows | `Stellio-Setup-<version>.exe` | 桌面应用 |
| 🪟 Windows 便携版 | `Stellio-v<version>-portable-win64.zip` | 桌面应用，免安装 |
| 🍎 macOS | `.dmg`（Apple Silicon `arm64` 或 Intel `x86_64`） | 桌面应用 |
| 🐧 Linux | `Stellio-v<version>-x86_64.AppImage` | 桌面应用 |
| 🍓 树莓派 / Linux | `install-pi.sh` | 服务器（浏览器） |
| 🖥️ Proxmox VE | `stellio-lxc.sh` | 一条命令创建 LXC 容器 |
| 📲 Android | 配套 APK | 参见 [远程与移动访问](zh-Remote-Access) |

所有文件都在 [Releases](https://github.com/stellio-app/stellio/releases) 页面，每个文件都附有 `.sha256` 校验值。

## Windows

1. 从 Releases 下载安装程序。
2. 运行 `Stellio-Setup-<version>.exe`。
3. 完成。

**便携版**：解压到任意位置（硬盘、U 盘），运行 `Stellio.exe`。您的数据保存在可执行文件旁的 `data` 文件夹中（请保留 `portable.flag` 文件）。

> ⚠️ 安装程序**未经代码签名**：Windows SmartScreen 可能会显示警告。如有需要可核对 `.sha256`；内置更新在安装前会进行校验。

> 💡 如果内置窗口无法打开（WebView2 或 `Python.Runtime.dll` 被阻止，常见于下载之后），Stellio 会在独立的 Edge/Chrome 窗口中打开，关闭该窗口时即停止运行。要恢复内置窗口：右键 zip → 属性 → **解除锁定**，然后重新解压。详情见 `data\stellio.log`。

## macOS

打开 `.dmg`，将 Stellio 拖入“应用程序”。请选择与您的 Mac 匹配的文件：`arm64`（M1、M2、M3……）或 `x86_64`（Intel）。构建未经公证：首次启动时，右键点击 → **打开**。

> 如果屏幕一直空白：5000 端口可能被 macOS 的“AirPlay 接收器”占用。此时 Stellio 会自动选择另一个空闲端口。参见 [故障排除](zh-Troubleshooting)。

## Linux (AppImage)

```bash
chmod +x Stellio-v*-x86_64.AppImage
./Stellio-v*-x86_64.AppImage
```
AppImage 内置更新信息（`.zsync`）。

## 树莓派 / Linux 服务器

**无界面服务器**模式：Stellio 在后台运行，通过浏览器使用。详情参见 [服务器版](zh-Server-Edition)。

```bash
curl -O https://raw.githubusercontent.com/stellio-app/stellio/main/install-pi.sh
chmod +x install-pi.sh
./install-pi.sh
```

## Proxmox VE

在 **Proxmox 主机的 Shell** 中：
```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/stellio-app/stellio/main/stellio-lxc.sh)"
```
详情参见 [服务器版](zh-Server-Edition)。

## 更新

- **桌面版**：Stellio 从 GitHub 检测新版本并应用 `.zip` 补丁（Windows、macOS 和 Linux 机制相同）。仪表盘上的“更新”小组件会打开更新窗口。
- **服务器版**：同样的自动更新，或使用 `update-stellio`（LXC 容器）/ `./install-pi.sh`（树莓派）。
- 每个版本首次启动时，缺失的模块（PDF 报价、表格导入、通知等）会自动下载。

# 快速上手
{{img:library}}

左侧栏是图标**导轨**；点击某个类别会在右侧展开其**面板**，选择后自动收起。

{{img:sidebar-panel}}


## 1. 首次启动
Stellio 会显示**引导式导览**和“快速上手”清单。您可以随时在设置中重新开始导览。

## 2. 创建账户
账户是**本地**的：密码 + 恢复码 + 密保问题。密码重置完全在本地完成，无需邮件和网络。

## 3. 添加来源
**来源**是存放模型的文件夹或共享：
- 本地文件夹、单个文件、**SMB** 或 **NFS** 共享；
- 在您的电脑上检测到的 3D 文件夹会被**推荐**，一键即可添加；
- 对每个来源，您可以选择显示哪些文件类型。

随后 Stellio 会扫描您的文件，并在后台生成 3D 缩略图。

## 4. 添加打印机（可选）
打开**打印机**页面：网络发现会列出检测到的设备。参见 [打印机](zh-Printers)。

## 5. 选择切片软件
Stellio 会自动检测已安装的切片软件（OrcaSlicer、Bambu Studio、PrusaSlicer、Cura 等）。发送按钮会直接在切片软件中打开文件。

## 仪表盘
主页汇总了正在进行的打印、低库存、最近的打印和最近的文件。**小组件**（约二十个）可通过拖放重新排序并可隐藏：当前打印、低库存、最新 S.O.S Print、建议、Stellio 实例、已完成项目、图库、报价等。

## 导航
左侧栏是一个**窄导航条**：主页、库、打印、耗材、工具和跟踪。点击某个类别即可打开它的**面板**，选择后面板会自动收起。类别下各页面的通知徽章会在其图标上**累加显示**。底部为：车间模式、帮助、**更新**和设置。**项目**和**已打印**位于“打印”类别中。

## 日常工具
- **命令面板** `Ctrl+K`：导航、执行操作、查找文件、标签、耗材盘或配置。
- **通知中心**（铃铛）：打印完成、失败、维护、低库存、耗材烘干。
- **悬浮小组件**：显示当前打印进度，所有页面可见。
- **键盘快捷键**：参见 [设置与数据](zh-Settings-and-Data)。

# 分步指南

Stellio 的每一项功能：**它有什么用，怎么用**。技术细节见其他页面；这里只讲操作。

> 💡 在整个应用中：`Ctrl+K` 打开**命令面板**（跳转到某处、执行操作、查找文件、标签或耗材盘），`?` 显示快捷键。

## 熟悉 Stellio 的界面

| **即将打印** | 您的打印等待列表，可重新排序。 |

| **打印机** | 实时监控、发送、维护、易损件。 |

| **统计** | 可靠性、消耗、格式、报告。 |

## 添加并找到我的文件

1. 点击**添加来源**（或按 `Ctrl+K` 再选“添加来源”），选择一个**文件夹**、单个文件或 **SMB / NFS** 共享。电脑上找到的 3D 文件夹会被推荐给您。
2. Stellio 在后台扫描并生成 **3D 缩略图**；您使用应用时，生成会暂停。
3. 查找模型：在**搜索**栏中输入，或用 AI 搜索以自然语言描述（“一个耳机支架”）。
4. 从文件资源管理器拖放 3D 文件，可直接添加。

💡 压缩包（ZIP、RAR、7z、TAR）无需解压即可浏览。

## 用标签、收藏和筛选来整理

1. 打开文件的 **⋯** 菜单，或选中多个文件（`Shift+点击` 选择范围）进行批量操作。
2. 手动添加彩色**标签**，或让 AI 推荐；按 `T` 打开标签管理器。
3. 点击星标将模型设为**收藏**（按 `F` 打开收藏夹）。
4. 组合**筛选**条件（类型、大小、重量、打印状态、“耗材库存”），然后**保存**该筛选以便复用。
5. 批量重命名：使用**批量重命名**（查找/替换、前缀、后缀、编号），确认前可预览。

## 在 3D 中查看并准备模型

1. 点击文件的缩略图：**3D 查看器**打开（可离线使用）。
2. 旋转并缩放；对于多盘 3MF，可在各个盘之间切换。
3. 运行**可打印性分析**（悬垂）：Stellio 会推荐合适的**摆放方向**。
4. 使用**自动摆放**，把多个零件排布在打印机的热床上。
5. 在查看器中把结果发送到切片软件。

## 修复损坏的网格

1. 打开**修复**：Stellio 列出带有孔洞或开放边的文件（创建缩略图时也会在后台进行分析）。
2. 选择文件并开始**修复**；对比**修复前 / 修复后**。
3. 文件会就地修复；同时保留一份 `.bak` 安全副本以防万一。

## 转换文件

1. 打开**转换器**，选择一个或多个文件（STL、3MF、OBJ、PLY、AMF、STEP）。
2. 选择输出格式：STL、3MF、OBJ、PLY、OFF 或 GLB。
3. 如有需要，勾选**自动修复网格**和**删除原始文件**。
4. 开始。批量转换可随时取消：已转换的文件会保留。

## 将模型放大到等身大小（BigPrint）
BigPrint（**工具**菜单）可将模型放大到所需尺寸——1.8 米甚至更大——并切成适合您打印平台的部件：部件掏空、带拼接销钉，每个部件上刻有编号。计算由集成在 Stellio 中的开源引擎 [bigprint](https://github.com/PooterTF/bigprint)（AGPL-3.0，作者 Michael Christopher Stone）完成。

{{img:bigprint}}

1. 选择模型：**从库中选择**、**导入文件**，或在文件的**操作**菜单中点击**发送到 BigPrint**（STL、3MF、OBJ、PLY）。
2. 填写**最终尺寸**（高度、宽度、深度或缩放系数）和您的**打印机**（预设列表或自定义尺寸）。
3. 设置**强度**（用途、材料、掏空、外壳厚度）和**销钉**；高级选项（向上轴、边距、平滑等）默认折叠。
4. 点击**预览**：Stellio 以分解视图显示各部件、耗材重量、预估成本和部件表。计算可随时取消。

{{img:bigprint-result}}

选择保存位置（库来源、子文件夹，可新建文件夹，支持网络共享），然后点击**保存打印文件**：STL 部件、3MF 项目、销钉、报告和预览会复制到 `<模型>_bigprint` 文件夹。

预览之后如果修改了设置，请先重新预览再保存。

## 整理：重复文件与回收站

1. 打开**重复文件**：完全相同的文件，以及**几何相近**的文件（同一模型被改名或重新导出）会被归为一组。
2. 保留想要的那个，删除其余的。
3. 误删了？`Ctrl+Z` 可在 5 分钟内撤销；**回收站**保留得更久，可恢复或永久删除。

## 把文件归入项目

1. 打开**项目**并新建一个项目；添加同一物体的文件（主体、盖子、支撑……）。
2. 加入项目的**多盘** 3MF 会被拆分为每盘一个 3MF（也可使用 ⋯ 菜单中的**拆分打印盘**）。
3. 跟踪进度（“进行中” / “已完成”），点击**项目成本**为整套核算成本。

## 下载模型

1. 打开**下载**（或按 `Ctrl+N`），粘贴模型链接（Printables、MakerWorld、Thingiverse、Nexprint、Creality Cloud、Snapmaker Space）。
2. 首次需连接所要求的账号（参见[下载](zh-Downloads)）。
3. 选择目标**来源**：文件会连同其**出处**（链接、作者、许可证）一起保存。
4. Stellio 每天检查模型是否有**新版本**；**我的点赞**和**我的作品**可在已连接的账号上找到您的模型。

## 连接打印机

1. 打开**打印机 → 添加**：**网络检测**会推荐找到的设备；否则请填写类型、地址和访问密钥。
2. 填写**打印体积**（X、Y、Z）：零件过大时，Stellio 会在发送前提醒您。
3. 如有需要，选择**此打印机的切片软件**（1.0.8）：这台打印机将使用它打开文件。
4. 开启实用选项：**延时摄影**、**打印结束照片**、**AI 监控**、**智能插座**（真实耗电）。

## 把文件发送到切片软件

1. 在资料库或查看器中，点击**发送到切片软件**。
2. 在弹出的窗口中：查看**估算**（重量、时间），选择**打印机**、**耗材盘**和**设置配置**，或保持“自动”。
3. 阅读**打印前检查**：耗材盘需烘干、磨蚀性耗材、超出打印体积、材料不足。
4. 点击**发送**：文件会在该打印机的切片软件（或“设置”中的切片软件）中打开，并加载与该设备关联的配置。如果您选择了扣减，耗材盘会被扣除用量。

💡 若要把配置关联到某台打印机，请在“设置 → 切片软件”中导入。

## 为下一步做准备：“即将打印”

1. 在文件的 **⋯** 菜单中选择**加入即将打印**。
2. 打开**即将打印**：拖动即可**重新排序**。
3. 可直接把某一项发送到切片软件，或将其从列表中移除。

## 跟踪一次打印

1. 在打印机卡片上：温度、进度、**实时摄像头**以及当前文件名。
2. **悬浮小组件**在每个页面上显示进度。
3. **铃铛**会通知您（完成、失败、维护、库存不足）；开启**推送通知**（ntfy、Gotify、Pushover、Telegram、Discord、Slack、webhook），即使窗口关闭也能收到。
4. 到 100% 时，Stellio 会拍摄**结束照片**：一键标记为*成功*或*失败*。**延时摄影**会自动合成。

## 评价、重新打印、查找照片

1. 打开**历史记录**：可按平台、结果或日期筛选。
2. 把每次打印标记为**成功**或**失败**：这会用于优化推荐和统计。
3. **查看文件**，或像上次一样**重新打印**（相同设置）。
4. 在**图库**中找到您的照片；**我的 G-code** 保存与文件关联的 G-code，并提供**在切片软件中打开**按钮。

## 跟踪我的耗材盘

1. 打开**耗材库存**：手动添加耗材盘（或导入 Excel/CSV），连接 **Spoolman**、**TigerTag** 或 **OpenPrintTag**，也可在 **Open Filament Database** 中查找耗材。
2. 发送到切片软件时选择耗材盘：Stellio 会**扣减**用量，并检查剩余是否足够。
3. 在**称重与预测**中为耗材盘称重：Stellio 会估算其**用完日期**，临近时提醒您。
4. 记录耗材盘的**烘干**以跟踪状态；使用**再次购买**打开厂商的商店。

## 计算成本并生成报价单

1. 在文件（**成本**）或项目（**项目成本**）中打开计算器。
2. 检查材料、电费、**设备损耗**、**固定费用**、**利润率**和**数量**：单价和总价会随之显示。
3. 点击**生成报价单（PDF）**：填写客户和描述。PDF 会被保存，可在**报价单**小组件中找到。
4. 在**设置 → 打印定价**中设置默认利润率。

## 管理订单、客户和发票

1. 在设置中开启*启用成本、报价和开票功能*：**管理**界面随即出现。
2. 把报价单连同**跟踪链接**发给客户：客户可在线接受或拒绝；接受后会创建打印任务。**Stellio 不处理任何付款。**
3. 跟踪**订单队列**、付款、定金发票和红字发票；**智能分配**会推荐合适的打印机，但绝不会自行开始打印。
4. 每月导出**会计资料**（含 CSV 和 PDF 的 ZIP）。

## 安排生产（计划与产能）
**计划**页面（**打印**菜单）会为每台打印机算出每个订单的预计完成日期，对比可用产能与需求负载，并在过载或延误发生之前提醒您。

{{img:planning}}

1. 在**订单**中为每个订单填写**单件耗时**（小时）：由报价生成的订单会从成本核算中带入。没有耗时的订单不会被排程，并在页面顶部提示（可直接在那里补填）。
2. 为每个订单选择**打印机**（否则 Stellio 会建议放到最先空闲的机器上）并填写**交付日期**。
3. 打开**计划**：条形图显示各打印机上订单的先后顺序（红色=预计延误，橙色=余量不足一天），并给出每台机器的**负载率**。进行中的打印会根据从打印机读取的剩余时间计入。
4. 设置**范围**（7、14 或 30 天）。顶部卡片汇总产能、负载、预计延误以及近 90 天的**按时交付率**。

**打印机产能**：按机器填写每天可打印的小时数和工作日（默认 16 小时、每天）；取消勾选可将打印机排除在计划之外。

当订单将超过交付日期或打印机过载时，Stellio 会发送通知（每个订单每天一次）。

计算刻意保持简单：使用您填写的耗时，按交付日期依次排列订单，不考虑换料或故障。

## 找到最佳组合（可追溯性）
**可追溯性**页面（**打印**菜单）会把每次打印关联到所用的**确切模型版本**和**切片配置**，并为每个模型显示效果最好的组合。

{{img:trace}}

1. 照常在 Stellio 中打印：打印会自动关联到模型。如果文件自上一版本以来有变化，Stellio 会保存一个“打印前”版本，因此关联始终准确。
2. 打印后在历史记录中**为结果评分**（成功、失败、部分）：成功率就来自这些评分。
3. 打开**可追溯性**：每个模型一行，显示其版本和**最佳组合**（版本 + 配置，已评分打印中的成功次数）。点击即可打开**模型版本**。
4. 在**模型版本**中，每个版本都会显示成功、失败次数和成功率，表格按**版本 × 配置**交叉统计。

{{img:trace_versions}}

## 大型模型
STL 加载到内存后约占其大小的 12 倍。超过阈值（256 MB；电脑空闲内存充足时最高 1 GB）后，Stellio 不再完整加载：以流式方式分析（二进制和文本 STL），缩略图和查看器使用**简化版本**（约 300,000 个三角形），写入操作（修复、转换等）会被拒绝并给出明确提示。

## 树脂
侧边栏的分类现在名为**材料**，包含两个页面：**耗材**（料盘库存）和**树脂**。树脂库存为**手动管理**：添加树脂瓶（名称、品牌、类型、颜色、容量、剩余量、价格、存放位置、备注），并用“使用”按钮扣除指定毫升数。自 1.1.8 起提供**自动消耗**（树脂页面底部）：为每台树脂打印机选择**当前树脂瓶**；打印结束时，Stellio 会从该瓶中扣除已用树脂。用量优先读取 `.sl1` 文件（`usedMaterial` 字段）；否则按资料库中同名模型**估算**（闭合网格体积 + 15% 的支撑与损耗余量）并标注为估算；没有可靠数据时**不扣除**，并会通知您。打印失败时只扣除已打印的部分（需已知进度）。每次扣除都记入历史，可**撤销**；剩余量不会低于零。

## S.O.S Print
对打印故障进行**自适应**诊断：
1. 您描述问题（每一步都可附照片），也可以提供所用设置（温度、速度、回抽等）。 **速度**会从所选切片软件配置中读取（或由您填写）；缺失时 AI 会询问。 对于**多色**打印，AI 会关注**擦拭塔**（脱落、倒塌、砸到模型、颜色混杂）并提出针对性的问题；塔宽度从配置中读取。 从第一步起以及每次回答之后，AI 都会显示**按概率排序的假设**（%），并附上原因或快速检查方法。

## 启动时屏幕一直空白（macOS）

## LXC 容器无法访问
在 Proxmox 的 shell 中：
1. `pct status <CTID>`，如果已停止则执行 `pct start <CTID>`。
2. `pvesm status`：**存储已满**？当存储为共享时，这是最常见的原因。
3. `pct exec <CTID> -- free -m` 和 `dmesg -T | grep -i "oom\|killed process"`：内存不足。
4. `pct exec <CTID> -- ip -4 a`：DHCP 分配的 IP 是否变了？请在路由器上为其预留。
5. `pct exec <CTID> -- systemctl status stellio` 和 `journalctl -u stellio -n 100`。

自 1.0.7 起，自动监控会处理常见情况；参见 `journalctl -t stellio-watchdog`。

# 插件

插件是一个小型 Python 程序，用于响应 Stellio 的事件（打印完成、打印失败、订单逾期、打印机过载）：发送通知、写入电子表格、打开灯……插件由作者发布在 **GitHub** 上；Stellio 在 **插件 › 目录** 菜单中显示**公共目录**（徽标 + 描述），一键即可安装。

每个插件都带有徽章：托管于 `stellio-app/stellio-plugins` 仓库的为**官方**，托管在其他位置（或通过 .zip 安装）的为**社区**。Stellio 根据压缩包的真实地址决定徽章：请务必查看社区插件的权限和代码。

**插件安全（1.1.8）。** 安装前，Stellio 会**审计代码**（静态分析：未声明的网络使用、启动进程、动态代码、二进制文件等）；出现阻止项时会拒绝安装，除非您明确接受风险。目录和插件可以**签名（Ed25519）**：一旦配置了受信任密钥，无效签名、未签名的官方插件以及已签名插件的未签名更新都会被拒绝（未配置密钥时仅 SHA-256 校验和提供保护，插件页面会说明）。在 **Linux** 上，内核还会限制每个插件：文件只读（仅可写入其 `data/` 文件夹），没有 `network` 权限则无法联网；**在 Windows 和 macOS 上不会应用这些限制**：权限仍是声明式的。签名证明来源而非无害，审计也可能漏掉隐藏代码：请务必阅读代码。

**内置插件。** Stellio 的部分功能以内置插件形式提供（BigPrint、树脂、USB 打印机、延时摄影、文件工具、打印板工作室、推送通知、Webhook、定期摘要、MQTT / Home Assistant、Obico、共享与同步、Spoolman、AI 提供商与 AI 助手、Stellio Pro）。它们包含在应用中，但只有启用后才会加载（插件页面的“内置插件”部分；更改在重启后生效）。**从旧版本升级：无需任何操作。** 首次启动 1.1.7 时，你正在使用的插件（例如已启用的 MQTT、USB 打印机、Webhook、延时摄影）会自动启用，并完全保留原有设置；没有设置的工具（BigPrint、文件工具、打印板工作室）保持原样。全新安装不会启用其中任何一个。停用插件不会删除其设置。 其他内置插件：共享与同步、Spoolman、每个 AI 提供商一个插件 + AI 助手（启用全部 AI 功能），以及 **Stellio Pro**（客户、报价、发票、订单、会计、电价、排程、物料需求、零件库存）：仅在启用时添加各自的页面和按钮。

## 创建插件
### 1. 结构
插件是一个扁平文件夹，包含一个 `plugin.json` 文件和一个 Python 脚本：
```
mon-plugin/
├── plugin.json     清单（必需）
├── main.py         入口脚本（名称任意，在 "entry" 中指定）
└── ...             其他文件：最多 100 个，解压后 8 MB
```

### 2. 清单 plugin.json
```json
{
  "id": "mon-plugin",
  "name": "Mon plugin",
  "version": "1.0.0",
  "api": 1,
  "description": "Écrit une ligne à chaque impression terminée.",
  "author": "Votre nom",
  "entry": "main.py",
  "events": ["print.finished", "print.failed"],
  "permissions": ["events"]
}
```
| 字段 | 作用 |
|---|---|
| `id` | 唯一标识：小写字母、数字、`-` 或 `_`，2 到 40 个字符 |
| `name`、`description`、`author` | 在 Stellio 中显示的文字 |
| `version` | 数字版本，例如 `1.2.0`；用于检测更新 |
| `api` | 插件 API 版本：`1` |
| `entry` | 根目录下的 Python 脚本（默认 `main.py`） |
| `events` | 监听的事件 |
| `permissions` | 请求的权限 |
| `ui` | 在 Stellio 中显示的页面：`title`、`icon`（Font Awesome）和 `entry`（`.html` 文件） |

### 3. 事件与权限
| 事件 | 触发时机 |
|---|---|
| `print.finished` | 打印完成 |
| `print.failed` | 打印失败 |
| `order.late` | 订单超过期限 |
| `printer.overload` | 打印机过载 |

| 权限 | 作用 |
|---|---|
| `events` | 接收事件（声明 `events` 时必须） |
| `api:read` | 通过 Stellio 公共 API 读取数据 |
| `api:write` | 通过公共 API 修改数据 |
| `network` | 说明性权限：插件会访问互联网 |
| `ui` | 在插件菜单中显示插件页面 |

### 4. 脚本
Stellio 在单独的进程中运行 `python -I main.py <事件>`，并通过标准输入发送 JSON `{"event": "...", "data": {...}}`。`-I`（隔离）模式不会把插件文件夹加入 Python 路径：若要导入插件中的文件，请自行添加该路径。标准输出会记录到日志中。
```python
import json, os, sys

payload = json.loads(sys.stdin.read() or "{}")
event, data = payload.get("event", ""), payload.get("data", {})
config = json.loads(os.environ.get("STELLIO_PLUGIN_CONFIG") or "{}")

print(f"{event}: {data.get('file_name') or data.get('printer') or '-'}")
```
要操作 Stellio（`api:*` 权限），脚本会收到 `STELLIO_API_URL` 和 `STELLIO_API_TOKEN`（取自插件配置中的 `api_url` 和 `token`）。Python SDK `stellio_sdk.py`（仓库的 `sdk/python` 文件夹）提供 `plugin_event()`、`plugin_config()` 和现成的客户端：把它复制到您的插件中，并在导入前加入 `sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))`。完整示例见 `sdk/examples/hello-plugin`。

限制：每次运行 10 秒，内存 512 MB，环境最小化（仅 `STELLIO_*` 变量和 `PATH`）。运行 Stellio 的机器上必须安装 Python 3。配置是键/值对列表（文本、数字、布尔值），最多 4000 个字符。

### 5. 测试
把文件夹的**内容**压缩为 `mon-plugin.zip`（最大 2 MB），在 **插件 › 目录** 中安装（本地压缩包），接受权限，启用并使用 **测试**。通过阅读日志来排查问题。

- 页面显示在**隔离**的框架中：无法访问网络、Cookie 或 Stellio 的其他部分。

- 主题通过 CSS 变量 `--st-bg`、`--st-panel`、`--st-card`、`--st-text`、`--st-muted`、`--st-border`、`--st-accent`、`--st-success`、`--st-warning` 和 `--st-danger` 提供，语言通过 `window.stellio.lang` 提供。

```js
document.addEventListener('stellio-ready', async () => {
  const list = await window.stellio.api('/api/gcodes?limit=50');
  const id = list.gcodes[0].id;
  const text = await window.stellio.api('/api/projects/gcodes/' + id + '/download', 'text');
});
```

试用方法：压缩 `mon-plugin` 文件夹的内容，在 **插件 › 目录** 中安装压缩包，接受权限并启用，然后从 **插件** 菜单打开。至少需要一个已归档的 G-code（文件详情或项目中）。已停用的插件在列表中显示为灰色。

## 进入 Stellio 目录
官方目录是仓库 `stellio-app/stellio-plugins` 中的 `catalog.json` 文件。通过 **Pull Request** 把您的插件加进去。

1. Fork 仓库 `stellio-app/stellio-plugins`。
2. 在 `catalog.json` 中添加您插件的条目：
```json
{
  "id": "mon-plugin",
  "name": "Mon plugin",
  "version": "1.0.0",
  "description": {"fr": "Écrit une ligne à chaque impression terminée.", "en": "Writes a line when a print finishes."},
  "author": "Votre nom",
  "url": "https://github.com/vous/mon-plugin/releases/download/v1.0.0/mon-plugin-1.0.0.zip",
  "sha256": "64 caractères hexadécimaux",
  "permissions": ["events"],
  "logo": "https://raw.githubusercontent.com/vous/mon-plugin/main/logo.png",
  "homepage": "https://github.com/vous/mon-plugin"
}
```
3. 提交 Pull Request：自动检查会验证链接、SHA-256 校验和与徽标，随后 Stellio 团队审阅插件。

| 字段 | 规则 |
|---|---|
| `description` | 简短（约 140 个字符）；纯文本，或每种语言一段文本（`fr`、`en`、`de`、`es`、`pt`、`it`、`zh`、`ja`） |
| `url` | 指向压缩包的 `https` 直链；`sha256` 必须完全一致 |
| `logo` | `https`，PNG、JPEG 或 WebP，最大 200 KB，建议 128 × 128（不接受 SVG） |
| `homepage` | 指向插件页面的 `https` 链接（可选） |
| `permissions` | 必须与清单中的权限一致 |

**更新**：发布新的 release，然后提交 Pull Request，修改 `version`、`url` 和 `sha256`。如果新版本请求额外权限，用户端的插件会被停用，直到用户接受这些权限；其配置会保留。

## 管理与被监督实例
**管理**插件（默认启用）把**访客账户及其角色**、团队、会话、审计日志和**实例**集中在一个页面（管理 › 管理）。
- **独立实例**（默认）：完全控制，一切照旧。
- **主实例**：“实例”子页列出已配对的 Stellio 实例，并可对其进行监督。
- **被监督实例**：其所有者**接受**后，账户、角色和权限只能从主实例管理；本地内容（库、打印机）保持私有，除非所有者在接受时另行选择；所有者可随时**退出监督**。
被监督实例不能监督其他实例，主实例也不能被监督。其余设置仍可在本地修改。
