# Atelier avancé (1.1.7)

Les outils de l'atelier avancé sont rangés dans la **barre latérale par catégorie** (compte propriétaire) : **Bibliothèque** (Organisation, Diff 3D, Similaires, Licences, Fiche pièce), **Impression** (Compatibilité, Vérif. impression, Archives G-code), **Matières** (Besoins matière), **Outils** (BigPrint, Plateau, Assistant fabrication, Communauté, Synchro) et **Administration** (Tâches, Base de données et la page **Administration**, qui regroupe Comptes, Équipes, Sessions, Journal d'audit et Instances). Chaque entrée se désactive dans Paramètres › Éléments de navigation. Les **plugins** ont leur propre menu dans la barre latérale (**Plugins › Catalogue**) (voir `docs/plugins.md`). Réservé au compte propriétaire. Chaque champ « Chemin du modèle » se saisit à la main **ou** se choisit dans la bibliothèque complète : bouton « Choisir dans la bibliothèque » → choix de la source, recherche, miniatures (sélection multiple pour le plateau et la communauté).

| Onglet | Ce qu'il fait | Limites assumées |
|---|---|---|
| Tâches | Suit les travaux de fond (indexation, diff 3D, synchro) : progression, annulation, pause. | File en mémoire : vide après redémarrage. |
| Journal d'audit | Qui a fait quoi, d'où ; export CSV. | Journalise les écritures, pas les lectures. |
| Équipes | Rôles des invités, permissions par dossier/projet, espaces de travail. | Une permission accorde, jamais ne retire plus que le rôle ne le permet pour un invité sans rôle. |
| Sessions | Appareils connectés (adresse IP, navigateur, dernière activité) ; révocation d'un appareil ou de tous les autres. | Coupure effective à la requête suivante, au plus 15 s ; deux appareils identiques (même navigateur, même IP) connectés à moins de 30 s d'écart sont comptés comme un seul. |
| Compatibilité | Volume, buse et matière d'un modèle face à chaque imprimante. | Dimensions issues de l'analyse du fichier ; spécifications des imprimantes à renseigner. |
| Organisation | Règles (extension, nom, licence, matière…) → déplacer/étiqueter. Aperçu, confirmation, annulation. | Les « suggestions de dossier » ne sont jamais appliquées seules. |
| Diff 3D | Compare deux versions d'un modèle (STL, OBJ, 3MF, PLY, OFF **et STEP**, lu par le même lecteur que le reste de l'application ; « version A / B » = numéro affiché dans la liste des versions) : métriques et **nuage de points coloré** (rouge retiré, vert ajouté, gris inchangé), rotation à la souris, zoom, vues dessus/face. | Comparaison par échantillonnage de surface, pas booléenne exacte ; ne remplace pas un contrôle visuel. |
| Similaires | Pièces de forme proche (empreinte D2 + proportions). | Aide au tri : deux pièces différentes de même silhouette peuvent sortir proches. Index à construire (voir le chiffrage). |
| Synchro | Synchronise un dossier avec celui d'une instance appairée (édition serveur). | Plan puis application confirmée ; **jamais de suppression** ; en cas de conflit les deux versions sont gardées ; fichiers verrouillés/en cours d'écriture non gérés. |
| Plateau | Disposition automatique sur **la vraie géométrie** (contours exacts, imbrication de formes concaves, rotation libre 90/45/30/15° ou aucune ; mode « boîte englobante » toujours disponible), plusieurs plateaux, marge. **Éditeur 2D** : glisser, pivoter de n'importe quel angle (contour recalculé par le serveur), aligner, pas réglable, clavier ; **vue 3D** des contours à leur vraie hauteur ; contrôle serveur (chevauchement des contours, sortie de plateau, hauteur) ; export 3MF d'une disposition retouchée. | Calcul sur une grille (≈ 1 mm pour 256 mm) puis contrôle exact : la marge réelle peut dépasser un peu celle demandée ; trous intérieurs non utilisés ; 3MF jamais ouvert dans un vrai slicer. |
| Communauté | Paquets `.stlpack` (licence obligatoire, empreintes sha256), étagère locale, échange entre instances appairées, signalement/masquage, **remix** (filiation + compatibilité de licence), **commentaires et favoris** (locaux à l'instance). | Pas de serveur central ; la modération est celle de chaque propriétaire. L'import ne s'exécute jamais, n'écrase jamais. |
| Archives G-code | Conserve (gzip + SHA-256, 200 Mo max) le G-code réellement imprimé d'une entrée de l'historique ; téléchargement identique à l'original. | Propriétaire uniquement ; l'archive est un fichier de plus sur le disque. |
| Licences | Échéances de licence (expirées / dans 60 jours) ; une notification (centre de notifications, notification native, push) est créée **une fois** par fichier et par état. | Dates saisies à la main ; rien n'est supprimé ni bloqué automatiquement. |
| Fiche pièce | Tout ce que Stellio sait d'un modèle sur une page : origine et licence (échéance), versions avec leurs impressions, meilleure combinaison version + profil, dernières impressions (imprimante, profil, résultat), G-code archivés, photos. | Lecture seule ; assemble ce qui est déjà enregistré (rien n'est reconstitué pour les anciennes impressions non rattachées). |
| Vérif. impression | Avant d'imprimer, à partir de la géométrie réelle (STL, 3MF, OBJ, PLY, STEP) : surface en surplomb (angle réglable, 45° par défaut), volume de supports **estimé**, surface de contact avec le plateau, élancement, maillage étanche, tient dans le volume d'impression. Essaie ~16 orientations (6 axes + grandes faces planes de l'enveloppe convexe), classe, conseille la meilleure et propose une **copie orientée** à télécharger (téléchargement géré par l'application, comme les autres fichiers). Le choix d'une imprimante remplit automatiquement les dimensions du plateau. | Estimation, pas un slicer : le volume de supports est une borne haute (supports posés depuis le plateau). Une orientation plate sur la plus grande face n'est pas toujours la meilleure pour la résistance des couches. Le fichier d'origine n'est jamais modifié. Complète (sans la remplacer) la vérification existante avant envoi (`/api/files/pre-print-check` : non-manifold, plateau, stock de bobine). |
| Besoins matière | Ce que demandent la file d'impression et les projets en cours (quantité restante × poids) face au stock, par matière : manque en grammes, bobines à commander (bobine de 1 000 g), autonomie observée. Complète la prévision de réapprovisionnement existante (`/api/filament/restock`), qui regarde le passé. | Le poids vient d'abord des impressions précédentes du fichier, puis du slicer/G-code, sinon d'une estimation géométrique × 0,35 **signalée comme telle** ; un poids inconnu n'est pas compté (et affiché). Une matière non indiquée est comptée en PLA (signalé). |
| Assistant fabrication | Questions sur la bibliothèque, les imprimantes et l'historique ; propositions à confirmer. | Requêtes d'un catalogue fermé ; l'IA ne fait que choisir. |

## Étude de coût — pièces similaires
Construire l'index : une empreinte par modèle de moins de 60 Mo, en tâche de fond. `GET /api/similar/status` donne le nombre de modèles indexés, la durée moyenne par modèle et la durée restante estimée ; l'index occupe quelques centaines d'octets par modèle. Un modèle non indexé est calculé à la demande.

## Similaires — indexation et modèles ignorés
L'indexation tourne en tâche de fond et s'affiche tout de suite, sans limite de durée (l'interface suit la tâche jusqu'à la fin). Un modèle illisible (fichier vide, corrompu, format non géré) est **compté comme ignoré** (table `shape_skip`) au lieu de bloquer la progression : `GET /api/similar/status` renvoie `indexed`, `total`, `missing` et `skipped`. Le filtre d'extension du sélecteur de modèle permet de ne lister que les STL, 3MF, etc.

## STL géants et version allégée
Seuil de chargement adaptatif : 256 Mo par défaut, jusqu'à 1 Go selon la mémoire libre. Au-delà, l'analyse se fait en flux (STL binaire, y compris à nombre de triangles erroné, et STL ASCII), avec miniature et viewer simplifiés. **Créer une version allégée** (`POST /api/files/lighten`, tâche de fond) écrit une copie « `<nom> (allégé).stl` » à côté de l'original, qui n'est jamais modifié (300 000 faces par défaut, minimum 20 000) ; un fichier invalide est refusé avec un message clair. Pour des modèles lourds, l'export STL / 3MF depuis le slicer reste souvent la meilleure réduction.

## Administration et instances supervisées

> **Visibilité** : les entrées Tâches, Base de données et Administration (et la catégorie du même nom dans la barre latérale) n'apparaissent que si cette instance est reliée à au moins une autre (appairage dans Paramètres › Instances Stellio), ou si elle a reçu une demande de supervision (pour l'accepter). Elles ne s'affichent jamais sur une instance supervisée. Une instance seule ne les affiche pas ; les comptes invités restent gérables dans Paramètres.
Plugin intégré **Administration** (`bundled_plugins/administration/`, actif d'office, désactivable dans Plugins › Plugins intégrés). La page Administration › Administration réunit cinq sous-onglets : **Comptes** (invités, rôles, mots de passe), Équipes, Sessions, Journal d'audit et **Instances**. Les modules qui appliquent les droits (`access_control`, `session_manager`, `audit_log`) restent dans le cœur : désactiver le plugin retire la page, jamais les protections.

Trois états : **autonome** (défaut, contrôle total), **principale** (au moins une instance supervisée) et **supervisée**. La principale envoie une demande à une instance appairée (table `remote_instances`, clé d'appairage de l'autre instance) ; la supervision n'existe qu'après **acceptation** par le propriétaire de l'instance visée, qui choisit alors de garder son contenu local privé (défaut) ou d'en exposer des totaux. Un jeton propre au lien (seule son empreinte est conservée) s'ajoute à la clé d'appairage pour toute commande.

**Demande de supervision** : sur l'instance visée, la demande s'affiche dans une popup **Accepter / Refuser** (avec la case « Garder le contenu local »), vérifiée toutes les 20 s et au retour sur la fenêtre. Sur la principale, le badge « En attente d'acceptation » passe tout seul à « Supervisée » (interrogation toutes les 4 s tant que la liste est affichée). L'onglet **Équipes** crée et supprime des équipes (espaces de travail), y ajoute ou en retire des comptes invités et fixe leur rôle dans l'équipe.

Sur une instance supervisée, les écritures sur les invités, rôles, permissions et espaces d'équipe (`/api/auth/guests*`, `/api/team/*`) répondent **423** `supervised` ; le reste reste modifiable. La principale gère les comptes à distance (rôle, création, suppression, mot de passe) ; le propriétaire local peut **quitter la supervision** à tout moment, la principale peut **libérer**. Une instance supervisée n'en supervise pas d'autres, et une principale ne devient pas supervisée. Routes : `/api/admin/*` (propriétaire) et `/api/peer/supervision/*` (clé d'appairage + jeton).

## Rôles
Propriétaire (compte) puis invités : **Administrateur**, **Gestionnaire**, **Opérateur**, **Utilisateur simple** (peut noter une impression et ajouter une photo de résultat), **Invité** (lecture seule). Les permissions par imprimante / projet / dossier s'ajoutent au rôle (une permission « aucun » refuse toujours). Voir la matrice dans `modules/access_control.py` (`RULES`).

## Organisation automatique — champs de règle
Extension, nom, licence, matière, taille, **auteur**, **catégorie**, **âge du fichier en jours** (`age_days` : plus grand / plus petit que). Aperçu, confirmation, annulation par lot.

## Grandes bibliothèques (test à 50 000 modèles)
Mesuré sur une bibliothèque générée de 50 000 STL (`tools/gen_library.py`), serveur réel et Chromium : analyse du dossier ≈ 12 s ; liste des fichiers 0,3 s ; premier affichage ≈ 3 s. Défauts trouvés et corrigés : étiquettes perdues au-delà d'environ 32 000 fichiers (limite de variables SQLite), grille dessinée en entier (1,8 M d'éléments → chargement au défilement au-delà de 1 000 modèles), analyses qui relisaient tout le fichier cache à chaque modèle (doublons géométriques 181 s → 4,6 s ; assistant 28 s → 1,5 s), réponse JSON de 17 Mo (compressée : 0,5 Mo).
**Limites connues** : mesuré avec des maillages minuscules (le coût de lecture de vrais modèles lourds n'est pas couvert) ; la recherche par forme et l'analyse de fond sur 50 000 vrais modèles prennent des heures ; le fichier cache reste un seul JSON (~20 Mo à cette taille). Le test a tourné sous Linux ; un disque réseau (SMB) sera plus lent pour l'analyse.

## Planning — rentabilité par imprimante
Tableau dans la page Planning (90 jours). Revenu d'une commande = total du devis réparti entre les commandes de ce devis au prorata des pièces faites ; coût = coût réel du modèle de coût (rebuts compris) ; heures = heures saisies, sinon durée estimée × pièces faites ; marge et marge par heure. **Limites** : une commande sans devis chiffré n'a ni revenu ni coût (comptée à part) ; le revenu n'est reconnu qu'à la pièce faite ; pas de temps de travail humain ni de coût d'amortissement hors du modèle de coût du devis.

## Statistiques › Stellio Intelligence

Sous les statistiques d'échecs : pour une matière et/ou une imprimante, le **profil de slicer recommandé** (borne basse de Wilson du taux de réussite, seuils : 3 impressions notées dans le périmètre, 2 pour un profil), ses réglages, les valeurs typiques des impressions réussies, les profils à éviter, et les **causes probables d'échec** classées avec leurs preuves (motifs déclarés, écarts de réglages entre impressions ratées et réussies, matière / imprimante / profil qui échouent plus que la moyenne). Routes : `GET /api/intelligence/overview|recommend|diagnose`.

Ce sont des **statistiques sur vos impressions notées, pas un modèle d'IA** : le périmètre s'élargit (modèle → matière + imprimante → matière → tout) quand les données manquent et l'interface l'indique ; sous 8 impressions notées, un compteur de progression s'affiche ; sans assez de données, la réponse est « pas assez de données ». Les causes sont des corrélations à vérifier, pas des preuves. Non testé sur un vrai historique.

## Planning › temps de travail humain

Chaque commande porte un temps de préparation (minutes, une fois) et un temps par pièce (retrait, finition, emballage), éventuellement des heures réelles. Multiplié par le taux horaire réglé dans le Planning (0 = non compté), il s'ajoute au coût de la commande et réduit la marge, la marge par heure et la rentabilité par imprimante.
